# H200 화자 재분리 비교 · 2026-10-21

65분 37.1306875초의 같은 녹음을 GPU 0~3에서 네 설정으로 분석했다.
각 설정을 두 번 실행했으며 모델 다운로드는 먼저 완료했다.
두 번 모두 각 설정의 화자 시간표가 완전히 같았다. 정확도 정답을 뜻하지는 않는다.

¹ 두 번째 실행에서 작업 PID의 `nvidia-smi` 메모리를 약 0.5초마다 읽은 최대값이다.
매 순간의 절대 최대를 보장하지 않는다. CUDA 컨텍스트를 포함하며 다른 프로세스의 메모리는 제외한다.
PyTorch 예약 Peak는 CUDA 할당자의 정확한 high-water mark이며 컨텍스트 등은 제외한다.
프로세스 CPU RSS 최대는 Nemotron 약 2.0 GiB, pyannote 약 4.0 GiB였다.

전체 시간은 126 MB의 PCM16 WAV를 SSH로 전송하고 별도 Python 프로세스를 시작해
모델을 로딩·분석하고 결과를 회수한 Mac의 실측 시간이다.
이미 만들어 둔 WAV를 사용했으므로 원본 M4A 등의 변환 시간과 최초 패키지·모델 다운로드는 제외한다.
따라서 앱의 첫 설치 시간이나 전사 전체 시간으로 사용할 수 없다.

## 화자 수와 정확도 해석

사용자가 확인한 녹음 맥락은 **주요 발화자 3명과 잠깐 참여한 다른 사람들**이다.
전체 화자 수와 구간별 정답 라벨은 아직 확정되지 않았다.
6명이나 4명이라는 결과를 과다 분리로 단정하거나, 3명 지정이 가장 정확하다고 판단할 수 없다.
3명 지정은 짧게 참여한 사람을 주요 화자에 합칠 수 있으므로 비교용 설정이다.
앱의 기본 인원수는 자동 판단을 유지한다.

Nemotron FP32가 감지한 여섯 그룹의 총 발화 시간은 약 1,167초, 1,116초,
540초, 87초, 49초, 21초다. 짧은 세 그룹이 실제 추가 참가자인지,
동일 인물의 다른 목소리·잡음인지 확인할 대표 샘플을 로컬 개인 검토 자료로 추출했다.
그룹별 시간에는 동시 발화가 포함될 수 있다.

사용자는 대표 샘플을 직접 듣고 두 모델 모두 유용하며, Nemotron이 잠깐 참여한 사람의
목소리를 잘 포착한다고 평가했다. 이는 이 녹음에 대한 청취 의견이며, 객관적 정확도 점수나
다른 녹음에서의 우위를 입증하지 않는다. 이 선호를 반영해 앱의 기본값은 Nemotron FP32로 정했다.

정답 RTTM이 없어 **DER·화자 정확도 점수는 계산하지 않았다**.
기존 MOSS 결과나 3명 지정 결과를 정답으로 삼지도 않았다.
본문은 재전사하지 않으며 MOSS가 만든 발화 구간과 새 음성 시간표를 겹쳐 화자 변경을 제안한다.
한 MOSS 발화 안에 여러 목소리가 있으면 검토 대상으로 표시하며 단어 경계를 임의로 생성하지 않는다.

## 실행 조건

- 서버: NVIDIA H200 4개, GPU별 143,771 MiB. 본 측정 두 회 시작 시 네 GPU 모두 기존 사용량·사용률 0으로 보고되었다.
- 음성: 단일 채널 16 kHz PCM16, 전체 녹음. 개인 음성·시간표·샘플은 저장소에 포함하지 않았다.
- Nemotron: `nvidia/Nemotron-3-Diarization`, revision `f667ed73aee57d40cc39428eb768b4fd87a0a29e`.
- Nemotron 실행: Transformers 스트리밍 API를 30.4초 오프라인 버퍼(`chunk_length=340`, `right_context=40`)로 설정하고,
  화자 캐시를 전체 녹음 동안 이어 갔다. 기본 0.5 임계값으로 구간을 추출했다.
  짧은 화자 그룹을 지우거나 임의로 3명에 맞추는 후처리는 하지 않았다.
- pyannote: `pyannote/speaker-diarization-community-1`, revision `3533c8cf8e369892e6b79ff1bf80f7b0286a54ee`.
  `speaker_diarization` 시간표를 사용하고 인원수 자동/`num_speakers=3`을 비교했다.
- Torch / torchaudio 2.8.0+cu128, Transformers 5.20.2, pyannote.audio 4.0.7,
  torchcodec 0.7.0, librosa 0.11.0, NumPy 2.2.6, CPU 스레드 4개.
- FP32와 BF16은 부동소수점 정밀도 비교이며, INT4/INT8 양자화는 사용하지 않았다.
- 모든 실험 종료 후 소유 GPU 자식 프로세스와 서버 임시 음성은 정리하고 설치 환경·모델 캐시는 유지했다.

재현: `scripts/benchmark-diarization.py --host <SSH 별칭> --audio <PCM16 WAV> --output <개인 결과 폴더>`.
네 GPU를 실제로 사용하므로 실행 전 사용 권한과 현재 상태를 확인한다.
집계 수치는 [JSON](2026-10-21-h200-diarization.json)에 보관한다.

## Mac 실행 확인

Apple M4 · 통합 메모리 16 GiB의 이 Mac에서도 같은 65분 37초 녹음을
Nemotron FP32 · 오프라인 · MPS로 한 번 분석했다. 추론 28.70초, 모델 로딩 포함
34.56초, Python 시작·결과 회수를 포함한 전체 36.90초였으며 6개 화자 그룹을 감지했다.
최초 설치·다운로드와 음성 변환은 제외한다. CPU 프로세스 Peak RSS는 0.81 GiB였지만
MPS GPU를 포함한 통합 메모리 Peak를 측정한 값은 아니다.
서버와 화자 수가 같다는 사실만으로 구간별 결과나 정확도가 같다고 판단하지 않는다.

## MOSS와 전사 전용 모델의 역할 비교

[MOSS 공식 구조](https://github.com/OpenMOSS/MOSS-Transcribe-Diarize)는 하나의
자기회귀 디코더가 본문·시간표·화자 태그를 함께 생성한다. 화자 분리를 별도 단계에서
실행해 시간을 더하는 구조가 아니다. 기존 65분·1청크 실측 528.92초 중
첫 토큰 이후 출력 생성은 525.99초(99.45%)였다.

같은 실행의 저장된 출력에 당시 모델의 고정 revision 토크나이저를 적용했다.
특수 토큰을 추가하지 않고 화자 태그 806개, 시간표 태그 1,612개를 순서대로 지운 뒤
재토큰화한 결과다. 시간표는 `\[\d+(?:\.\d+)?\]`, 화자는 `\[S\d+\]`로 식별했다.

| 출력 구성 | 토큰 수 또는 삭제 전후 차이 | 전체 대비 |
| --- | ---: | ---: |
| 전체 | 30,575 | 100% |
| 화자 태그 제거 차이 | 3,224 | 10.5% |
| 추가로 시간표 제거 차이 | 13,106 | 42.9% |
| 남은 본문 | 14,245 | 46.6% |

이는 출력 길이 분석이며 화자 분리의 연산량이나 실제 절감 시간을 측정한 결과는 아니다.
태그를 생성하지 않는 추론, 전사 전용 모델, 별도 정렬기를 실행한 실험과 구분해야 한다.
특히 53.4%를 그대로 시간 절감률로 사용할 수 없다.

전사 전용 모델과 Nemotron을 결합하면 모듈을 독립적으로 교체할 수 있지만,
화자 전환이 한 문장 안에 있으면 단어별 음성 시간 정렬이 필요하다.
[Qwen3-ASR-1.7B 공식 문서](https://huggingface.co/Qwen/Qwen3-ASR-1.7B-hf)는
한국어·문맥/전문용어 힌트를 지원하며, 단어 시간표에는 별도 Qwen3-ForcedAligner-0.6B를 사용한다.
해당 정렬기도 한국어를 지원한다. 공개 지원 범위가 이 개인 녹음에서의 우위를 뜻하지는 않는다.

현재는 전사 전용 모델의 한국어 정답 대비 CER, 고유명사·수치·부정어·발화 누락과
겹침 발화, 정렬·Nemotron을 포함한 전체 처리 시간을 비교하지 않았으므로 MOSS를 대체하지 않는다.
문맥을 이용한 단어 인식과 원문을 의역·재작성하는 작업도 구분한다.

## 구현 검증

원본 보존, 변경 발화 일부 승인, 오래된 분석 결과 거부, 외부 파일 변경 보존,
동일 출처 접근 제한, SSH 클라이언트 취소와 실제 supervisor의 EOF·무응답 lease 종료를 검사했다.
자동 검증 242개를 통과했다. Chromium과 WebKit에서 Nemotron 기본값, 두 모델의 세 설정,
Mac/SSH 선택·동의 안내 이미지·GPU·인원수·선택 해제된 결과 검토·일부 저장을 확인했다.
이는 기능 검증이며 화자 인식 정확도 평가와 구분한다.
