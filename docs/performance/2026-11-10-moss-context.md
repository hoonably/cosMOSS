# MOSS 자동 구간과 RTX 3090 90분 검증 · 2026-11-10

기존 길이별 측정에서 RTX 3090이 중단된 원인은 VRAM 70% 보호 한도였으며 실제 CUDA OOM이 아니었습니다. 이 보호를 제거하고 같은 90분 PCM 음성으로 확인한 결과는 다음과 같습니다. 다른 사용자의 작업은 중단하지 않았습니다.

| 조건 | 결과 | 작업 소유 GPU 프로세스 메모리 최고치 |
| --- | --- | ---: |
| H200, 단일 90분 요청 | MOSS 응답 완료, Nemotron 제외 | 26.79 GiB |
| RTX 3090 24GiB, 단일 90분 요청 | HTTP 400, 입력 71,687토큰 > 한도 69,136토큰 | 20.03 GiB |
| RTX 3090 24GiB, 자동 45분×2 | MOSS·Nemotron·누락 구간 보완 전체 완료 | 15.60 GiB |

3090 단일 요청은 메모리가 가득 차기 전에 엔진의 입력 한도에서 거절됐습니다. KV 캐시 풀은 69,138토큰이었고 요청 입력 한도는 69,136토큰이었습니다. `allow-auto-truncate`로 음성을 잘라 통과시키지 않습니다.

최종 전체 작업은 324.160초(모델 준비·전환 167.794초, 처리 156.365초), 정상 종료 코드 0, 발화 469개, 마지막 시각 5,400초였습니다. 최초 두 구간 뒤 기본 누락 구간 보완 요청 1회가 있었으며, 메모리·입력 한도 오류 재시도는 없었습니다. 실제 GPU 1장만 사용했습니다. 다른 장치에서 생성된 대본과 정확도를 평가한 실험은 아닙니다.

현재 예측은 363초로 실제보다 약 12.0% 길었습니다. 단일 입력의 한 번 검증이며 일반적인 예측 오차를 확정하는 자료로 사용하지 않습니다. 임시 WAV·대본·실행 소스·원격 작업 폴더는 제거했고 소유 프로세스 0개, GPU 잠금 해제, GPU 잔여 사용량 1MiB를 확인했습니다. 사용자 원본과 설치된 모델·실행 환경은 유지했습니다.

## 초기 구간 추천

전체 파일 길이 제한이 아니라 한 번에 넣는 구간의 추천 상한입니다. 다른 작업이 없는 GPU를 기준으로 실측 메모리 곡선과 엔진의 KV 예산을 함께 사용하고 5분 단위로 내립니다. 전체 파일은 추천 상한 이내의 최소 개수로 균등 분할합니다. 예를 들어 24GiB에서 90분 파일은 45분×2개입니다.

| 전체 VRAM | 초기 구간 상한 추정 | 90분 파일 분할 |
| ---: | ---: | --- |
| 8 GiB | 5분 | 5분×18 |
| 12 GiB | 25분 | 22.5분×4 |
| 16 GiB | 40분 | 30분×3 |
| 20 GiB | 60분 | 45분×2 |
| 24 GiB | 80분 | 45분×2 |

다른 용량에 대한 공통 곡선의 전환점은 30분 약13.05GiB, 45분 약16.21GiB, 60분 약19.37GiB, 75분 약22.53GiB, 90분 약25.69GiB입니다. H200·Ada는 각각 해당 GPU의 실측 메모리 곡선을 우선하며 90분 구간을 유지합니다.

24GiB의 KV 풀 실측을 다른 용량으로 확장한 추정입니다. 80분 단일 요청을 완료 검증한 것은 아니며, 저용량 GPU에서 모델 자체가 기동할지도 아직 검증하지 않았습니다. 현재 여유 VRAM, 드라이버·커널·입력 프롬프트 등에 따라 달라질 수 있습니다. 실제 CUDA OOM·입력 한도가 발생하면 완료한 구간을 보존하고 실패 구간만 줄여 새 워커에서 재시도하며, 모델 기동 실패나 재시도 한도 도달은 오류 카드로 남깁니다.
