# H200 전사 파이프라인 비교 · 2026-10-21

앱과 분리해 수행한 독립 실험 기록이다. 같은 65분 37.1306875초 녹음을 GPU별 한 장에서 처리했다.
속도 차이에 청크 분할·배치 효과가 섞이지 않도록 MOSS도 같은 짧은 청크·배치 조건으로 추가 측정했다.

이후 앱 적용과 실제 실행 경로 검증은 [앱 통합 검증](2026-10-21-app-pipelines.md)에 별도로 기록했다.

MOSS에는 전사와 자체 시간표·Nemotron·화자 연결이 포함된다. 음성 특징 처리와 결과 직렬화도 포함한다.
최초 다운로드·파일 전송·입력 음성 변환·모델 로딩·워밍업은 제외한다.

배치 23은 23청크를 한 번에 처리한다. 각 구성은 GPU 한 장만 사용한다.

## 해석

- MOSS 1청크 499.07초에서 같은 MOSS의 23청크·배치 23은 76.74초로 줄었다. 약 6.50배 차이의 상당 부분은 청크·배치 최적화 효과다.
- 같은 23청크·배치 23에서 Qwen 조합은 46.58초다. MOSS 조합보다 약 1.65배 빠르며 프로세스 Peak VRAM은 약 1.75배다.
- 같은 배치 8에서도 MOSS 99.51초·8.23 GiB, Qwen 56.21초·20.21 GiB다. Qwen이 약 1.77배 빠르지만 메모리는 약 2.46배다.
- Qwen 배치 4는 80.23초·13.55 GiB로, 메모리를 줄이는 중간 선택지다. MOSS 배치 8은 99.51초·8.23 GiB로 더 적은 메모리를 사용했다.
- 한 녹음과 H200에서 관찰한 결과다. 다른 음성의 발화 밀도·길이, 다른 GPU, 다른 엔진에 이 배율을 그대로 적용하지 않는다.

## 직접 읽어 대조한 품질

초반, 9분대, 20분대, 32분대, 44분대, 56분대와 마지막 구간의 출력문을 직접 대조했다.
이 평가는 전사문을 읽어 본 평가이며, 원음에 대한 독립적인 청취 정답 검증은 수행하지 못했다.
사람이 만든 정답 전사문·화자 구간표가 없으므로 CER·WER·DER·정확도 점수는 산출하지 않았다.

- 주요 대화 내용과 논의 순서는 양쪽이 대체로 비슷하게 유지했다.
- Qwen은 문장부호가 더 정리되어 있고, 문맥상 `빈칸`, `강건`, `각 요청`처럼 타당하게 보이는 표기를 냈다. MOSS에는 이에 대응하는 어색한 표기가 있었다.
- 기술 용어에서는 MOSS가 더 타당하게 보이는 경우도 있었다. 예를 들어 문맥상 backbone에 해당하는 부분에서 MOSS는 `백본`, Qwen은 `패콘`으로 옮겼다. verification 관련 표현에서도 Qwen이 더 어색한 음차를 내는 구간이 있었다.
- MOSS 역시 영문 약어·학회명·기술 용어를 올바른 영문 표기로 복원하지 못하는 부분이 있으며, 짧게 나눴을 때 원래 긴 문맥 결과와 표현이 달라진다.
- 마지막 짧은 발화처럼 의미가 크게 달라지는 출력도 있어, 자연스러운 문장만으로 정확도를 판단할 수 없다.
- 결론은 Qwen의 일방적인 한국어 품질 우위가 확인됐다는 것이 아니다. 속도 이점은 실측됐지만, 본문 정확도와 화자 전환의 최종 평가는 원음을 기준으로 확인해야 한다.

음성·전체 전사문·구간별 비교 페이지는 개인 검토 폴더에만 보관하고 이 저장소에는 포함하지 않았다.

## 시간 정렬과 화자 연결

Nemotron은 전사 모델의 출력과 별개로 원음 전체를 한 번 분석했다. 모든 구성에서 6개 그룹과 같은 화자 시간표를 반환했다.
이는 6명이 정답이라는 검증은 아니다. 주요 발화자 외에 잠깐 참여한 사람이 있다는 녹음 맥락을 존중하며 인원수를 강제하지 않았다.

Qwen 배치 23에서는 6,074개의 한국어 단어 정렬 항목 중 699개(약 11.51%)가 시작·끝 시간이 같았다.
이것이 단어 누락을 뜻하지는 않지만, 길이를 가진 구간의 시간 겹침만 이용하는 연결 방식에서는 문제가 된다.
이 단순 방식에서 미연결 항목은 777개였다. 해당 시점에 활성인 화자가 정확히 하나인 경우만 추가로 확인하면
548개가 대응되며 229개(약 3.77%)는 여전히 미연결·불명확한 상태다. 이 후처리를 앱에 넣지는 않았다.
화자 라벨이 붙었다는 것만으로 그 라벨이 정확하다고 판단하지 않는다. 겹침 발화와 화자 전환은 추가 검증 대상이다.

MOSS 시간표는 발화 구간 단위이고 Qwen 정렬은 단어 단위이므로 미연결 항목 수를 양쪽의 정확도처럼 직접 비교하지 않는다.
모든 완료 실행은 토큰 상한에 도달하지 않았고, Qwen의 마지막 정렬 시각은 원음 종료 약 0.30초 전이었다.
이 사실만으로 녹음 중간의 단어 누락이 없음을 보장하지는 않는다.

## 반복과 측정 범위

MOSS 배치 23과 Qwen 배치 4·8·23은 각 두 번 실행했다. 같은 설정의 반복에서 전사문과 시간표가 완전히 같았다.
반복이 없는 MOSS 1청크·MOSS 배치 8·Qwen 배치 1은 각각 한 번의 관측값이다. 통계적 신뢰구간을 제시하지 않는다.
기존 MOSS 65분 실험의 528.92초와 이번 실행은 출력도 달랐다. 과거 값 대신 이번 새 실행끼리 비교했다.
단일 실행의 출력 길이·시간 변동을 제품의 성능 개선으로 해석하지 않는다.

서버의 다른 프로세스를 종료하지 않았다. 사용자에게 사용이 허용된 GPU 0~3에 각 실험을 분산했고,
프로세스별 메모리를 측정했다. 자동 GPU 점유 프로그램과 시작 시점의 부하가 있으므로 완전한 독점 측정이라고 주장하지 않는다.
전송·설치 시간을 섞지 않았으며 Python 시작·모델 로딩·워밍업까지 포함한 별도 process 시간도 JSON에 기록했다.

## 실행 조건과 재현 자료

- GPU: NVIDIA H200, GPU별 143,771 MiB. 각 구성 한 장.
- 입력: 같은 SHA-256의 단일 채널 16 kHz PCM16 WAV, 길이 3937.1306875초.
- Torch 2.8.0+cu128, Transformers 5.20.2, CPU 스레드 4개, SDPA, greedy, seed 0.
- MOSS·Qwen·정렬기는 BF16, Nemotron은 FP32. 양자화·torch.compile·vLLM은 사용하지 않았다.
- MOSS의 실험용 배치는 공개 processor의 여러 오디오 입력을 사용하고, causal generation에 맞춰 오른쪽 패딩을 왼쪽 패딩으로 이동했다. 제품 코드에는 이 경로를 추가하지 않았다.
- 각 청크의 MOSS 화자 ID는 지역 라벨이므로 전역 인원수로 세지 않았다. Nemotron의 전체 녹음 시간표로 화자 연결을 비교했다.
- Qwen의 한국어 정렬에는 soynlp 0.0.493을 사용했다.
- 배치에서 남은 패딩을 포함할 수 있는 진단용 generated_tokens는 모델 간 성능·품질 지표로 사용하지 않았다.

모델과 소스 해시·정확한 반복 수치는 [JSON](2026-10-21-h200-asr-comparison.json)에 기록했다.
개인 실험 폴더의 `worker.py`, `supervisor.py`, `launch.py`, `split_audio.py`, `analyze.py`를 보관했다.
작업은 SSH 생존 신호와 소유 자식 프로세스 그룹으로 관리하고, 완료 후 GPU 프로세스를 해제한다.

공식 자료: [MOSS](https://github.com/OpenMOSS/MOSS-Transcribe-Diarize),
[Qwen ASR](https://huggingface.co/Qwen/Qwen3-ASR-1.7B-hf),
[Qwen ForcedAligner](https://huggingface.co/Qwen/Qwen3-ForcedAligner-0.6B-hf).

앱의 모델 선택·예상값·노트·실행 중 프로세스는 변경하지 않았고, 빌드·커밋·푸시·배포도 하지 않았다.
